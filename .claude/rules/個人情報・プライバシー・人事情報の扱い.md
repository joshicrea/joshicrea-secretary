# 個人情報・プライバシー・人事情報の扱い

Markdown（`.md`）を読み込んで加工する場合（要約・抽出・分析・転記・再構成・コメント生成など）および書き出す場合（新規作成・追記・更新・議事録化・書き起こし整形など）に、以下の内容はルールとして除外する。残してもナレッジ価値が低く、共有リスクが高いため、削除する方向で扱う。

## 1. 個人に対する感情的な表現

対象は特定の人物を指すときに限る。業務・施策・商品への感想のみ（「この構成は嫌だ」等）は除外対象外。

### (a) 嫌悪・強い否定的感情（人に向けたもの）

- 「この人が嫌い」「あの人嫌い」「〇〇が嫌だ」（人物に対する嫌悪として述べられている内容）
- それに準ずる、個人を貶すための感情的な言い回し

### (b) 個人を対象にしたネガティブな意思・打算

- 「この人をクビにしようと思う」「解雇したい」「やめてもらいたい」など、特定個人の雇用・関係を切る方向の発想
- 「（自分が）退職を考えている」「辞めたい」など、本人の退職意向が個人攻撃や人事トラブル文脈で他人向けに書かれている部分
- 「〇〇との契約を切ろうと思う」「契約を終了させたい」など、特定の個人・個別契約を対象にしたネガティブな意思表示

## 2. 会社の人事に関する情報

### (a) 契約・雇用のネガティブな決裁前情報

- 「この人との契約をなくそう」「契約を打ち切る予定」など、特定者に紐づく契約解消・不採用・降格等のネガティブ情報
- 採用見送り・パフォーマンス問題を特定個人が特定できる形で残す内容

人事・組織の方針・手順・ノウハウとして誰も特定されない形（「契約更新時のチェックリスト」等）なら残してよい。特定の誰かに対する否定的な意思・内密の人事判断は載せない。

## 3. 個人特定情報

- 特定個人への言及 → 「Aさん」等に変換
- 愚痴・不平・悪い噂・人格攻撃
- 名指しの批判・トラブル言及
- 人事に関する内密情報（解雇・契約解消等）
- 個人に対する嫌悪・強い否定的感情

## AI・編集時の扱い

- 読み込み時: 上記に該当する箇所は要約・引用・分析結果・派生ドキュメントに転記しない。元ファイルを編集する権限があれば削除またはぼかし（「一部メンバーについての人事的な発言あり」程度に置換可）
- 書き出し時: 新規・更新の成果物に上記カテゴリを書かない。入力データに含まれていれば出力から省く
- 境界が曖昧なときは、共有リポジトリに残すかで判断し、迷ったら載せない側に倒す

## フォーカスするもの

- 顧客の心理パターン
- セールス・コンサルの知見
- ノウハウとして再利用できる情報
