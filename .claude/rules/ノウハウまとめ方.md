# ノウハウ系まとめ方

ノウハウを抽出してナレッジ・マニュアルとして整備するときの共通ルール。マニュアルフォルダには目的別にファイルをしっかり分ける。

## 1. ファイルの役割と命名

1ファイル1役割。名前を見れば中身が想像できるようにする。

役割に応じた命名:
- パート・完全構造: 〇〇パート、〇〇パート完全構造（ヒアリング→構造→テンプレートまで）
- フレームワーク: 〇〇フレームワーク（横断で使う分析の型・手順）
- ストック・DB: 〇〇データベース、〇〇DB、〇〇事例集（選んで使うリスト）
- プロンプト: 〇〇プロンプト（具体的な指示を書いて使うもの）

## 2. 内容の構成

- 参照元を明示する（出典・取得元・作成日）
- 具体例を入れる（抽象論で終わらせない）
- 流れと中身を分ける（手順とテンプレを混ぜない）
- 判断基準を明記する（「いつ使うか」「どう使い分けるか」）

## 3. フォルダ構成

- テーマごとに1フォルダ、階層を深くしすぎない（最大3階層が目安）
- 同じテーマのファイルは同じフォルダに集める
- 横断で使うものは「共通」「フレームワーク」のような独立フォルダに

## 4. 更新ルール

- 追記は出典付きで（YYYY-MM-DD・どこから抽出したか）
- 古い情報は明示的に置き換える（「v2」「最新版」等で混在を避ける）
- 大きな改訂があったときは更新履歴を末尾に追記する
