# 出力形式・改行ルール

ファイルの用途によって改行の扱いを分ける。共通して守るのは「空白行による段落区切り」だけ。

## 共通ルール: 空白行は必ず入れる

用途を問わず、意味のまとまりが変わるところには空白行（1行空き）を入れる。Chatwork・LINE等にコピーしたときにも段落が分かれて読みやすくなるように。

- 話題・論点が変わるところ
- 話者が変わるところ（書き起こし）
- 見出しの前後

空白行を省略して文章を詰め込まない。

## Markdownの装飾（共通）

マーケ文章に限らず、議事録・社内報告などデータ格納系の `.md` も含め、本文では次を守る（詳細は「AIっぽい表現を避ける」を参照）。

- `**` による強調（太字）は使わない（別ルールで必須の台本マーカー等を除く）。語句を際立たせるときは「」（鉤括弧）で囲む
- 本文中に単独行の水平線 `---` を置かない。区切りは見出しと空行だけ

## マーケティング文章: 短い行で改行する

メルマガ・X投稿・広告文案・セールスレター・LP・SNS投稿文・台本など、読者に届ける文章では、1行を短く区切ってハードブレイクを入れる。

- メルマガ: 1行25〜30文字
- X投稿: 1行25文字前後
- LP・広告: 1行25〜30文字
- 台本: 1行20〜30文字
- ブログ: 段落単位（無理に折り返さない）

理由: スマホ表示やチャットへのコピペで横に詰まるのを防ぐ。行が短い方がリズムが出て読まれやすい。

## データ格納・ナレッジ系: 横幅制限なし

議事録・ノウハウ・フィードバック・書き起こし・マニュアル・分析レポートなど、データとして格納するファイルでは、1行の文字数に上限を設けない。

- 1文が自然に終わるところで改行すればよい
- 無理に25文字で折り返さない
- 段落の区切り（空白行）はしっかり入れる
- 長い段落は2〜4文ごとに改行して段落に分ける

理由: データ量が多いファイルを短い行で折り返すと、かえって読みづらくなる。段落区切りさえ入っていれば横幅は自然な長さでよい。

## 適用の判断基準

| 用途 | 横幅制限 | 空白行 |
|------|---------|--------|
| メルマガ | 25〜30文字 | 必須 |
| X投稿 | 25文字前後 | 必須 |
| LP・広告 | 25〜30文字 | 必須 |
| 台本 | 20〜30文字 | 必須 |
| ブログ | なし（段落単位） | 必須 |
| 書き起こし | なし | 必須 |
| 議事録 | なし | 必須 |
| ノウハウ | なし | 必須 |
| フィードバック | なし | 必須 |
| マニュアル | なし | 必須 |
| 分析レポート | なし | 必須 |

迷ったら「誰かに読ませる文章か」「データとして保管する文章か」で判断する。前者は短い行、後者は横幅制限なし。
