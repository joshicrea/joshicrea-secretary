# 段階的保存方式（データ書き出しの鉄則）

長いデータや大きなファイルを書き出すとき、一発で全部を書こうとしない。細かく・頻繁にファイルを確定保存しながら段階的に進める。「ネットワークエラーで全部消えてやり直し」を絶対に起こさない。

## なぜこのルールがあるか

- 長文データの書き出し中にネットワークエラーや処理中断が起きると、それまでの作業が全て消える
- ユーザーが再度同じ長文データを入力しなおす羽目になる
- 1時間のミーティング書き起こしに何時間もかかる事態が実際に起きている
- 「あと少しで終わるから一気に」という判断が一番危険。こまめに保存する方が結果的に早い

## 1回の書き出し量の上限（厳守）

| データの種類 | 1回あたりの上限 | 目安 |
|----|---|---|
| 書き起こしデータ | 5〜10分ぶん | タイムスタンプ5〜10個分 |
| 通常のテキスト | 30〜50行 | スクロール1画面分程度 |
| マニュアル・ノウハウ | 30〜50行 | セクション1つ分程度 |
| セールスデータ・分析 | 30〜50行 | 1つの分析ブロック程度 |

## 手順

1. Write で冒頭を確定保存（最初の30〜50行）
2. Edit で続きを追記（30〜50行ずつ）
3. 繰り返し（必要な分だけ）
4. Read で完了確認

## エラー時の挙動

- ファイルを読んで続きから再開する（最初からやり直さない）
- 同一エラーが2回続いたらストップ、アプローチを変更する
- 「あと少しで終わるから一気に」と判断しない

## 適用対象

30行を超える書き出しは必ず段階的保存方式を使う。短いMDの新規作成・更新は対象外。
