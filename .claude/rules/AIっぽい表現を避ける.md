# AIっぽい表現を避ける

このルールは、メルマガ・X・広告だけでなく、議事録・社内資料・月次報告・ナレッジ・マニュアルなど、新規作成・追記するMarkdown（.md）の本文に適用する。

AIが書いたとバレる装飾や定型があると、読み手は萎える。信頼を失う。

## 使わないもの（見つけたら直す）

### Markdownの `**` による強調（太字）は本文で使わない

AIが書いた最大の証拠のひとつ。一発でバレやすい。

```
NG: **ターゲットが合ってるか**が大事。
NG: 1. **インスタ運用を始める**
NG: これは**重要**です。

OK: 「ターゲットが合ってるか」が大事。
OK: 1. インスタ運用を始める
OK: これは「重要」です。
```

強調やスキャンしやすさが欲しいときは、原則として「」（鉤括弧）で囲む。`**` による太字は使わない（例外は別ルールの台本マーカー等のみ）。下線（￣￣￣）も特別な事情がない限り使わず、「」を優先する。

### 本文中の水平線（単独行の `---`）は使わない

Cursor や汎用AIがよく挙げる「ダッシュ3つ」は、セクション装飾として機械的に見える。本文では使わない。

- 区切りは見出し（`##` `###`）と空行だけで足りる
- 段落の区切りは空行のみ

YAMLフロントマター（`---` で囲む必須形式）、コードフェンス内の例示、globパターン（`**/*.md` 等）は技術要件のため除外する。

### 欧文ダッシュ（— / –）の多用は避ける

翻訳調・AI調になりやすい。日本語の本文では「、」「。」や括弧で十分なことが多い。

### その他の禁止表現

- 「〜における」「〜において」→「〜での」「〜で」に言い換える
- 「いかがでしたでしょうか」「結論として〜」などの定型句は使わない
- 箇条書きの乱用（文脈の中で自然に説明できるなら文章で書く）

## 避けるべき言葉

以下の抽象的な言葉は具体的な表現に置き換える。

| 避ける | 言い換え例 |
|--------|------------|
| 最適化 | 整える、調整する |
| 活用 | 使う、使い倒す |
| 向上 | 上げる、伸ばす |
| 提供 | 届ける、渡す |
| 網羅的 | 全部、すべて |
| 包括的 | まとめて、全体で |
| 〜における | 〜での |

## 文章の書き方

- 接続詞（また、さらに、そして、しかし）を文頭に連続で置かない
- 語尾を「〜です」「〜ます」だけで終わらせず、「〜だ」「〜ですね」「〜かもしれない」などを混ぜる
- 体言止めを適度に使ってリズムを出す
- 翻訳調の硬い表現ではなく、噛み砕いた自然な日本語で
- 「いかがでしたでしょうか」等の定型句禁止
- 箇条書きの乱用禁止

## 生成後のセルフチェック

コンテンツを生成したら、以下を確認する。

1. 本文・箇条書き・表のセルに、強調目的の `**...**` が残っていないか（コードフェンス内・別ルールの台本マーカーは除外）。際立たせたい語句は「」で囲めているか
2. 本文に、単独で並んだ `---`（水平線）がないか（YAMLフロントマターは除外）
3. 「AIが書いたっぽいな」と感じる部分がないか

感じたら即修正する。
