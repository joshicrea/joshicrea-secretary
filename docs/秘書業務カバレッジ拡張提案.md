# AI秘書 秘書業務カバレッジ拡張提案

作成日: 2026-07-13
対象: joshicrea-secretary（AI秘書プラグイン）
目的: ひとり起業家向けAI秘書の「秘書業務の網羅性」を引き上げる。brainオプトページの訴求（トータルでサポート）に実体を持たせる。

## 背景（調査で分かった事実）

既存14スキルを全ファイル横断で調べた結果、次の2点が判明した。

1. 個人依存はほぼゼロ。パス参照は全て「{{SECRETARY_BASE_DIR}}」プレースホルダーで書かれ、林大地個人のフォルダ・取引先・アカウントのハードコードは見つからなかった。個人性は「ユーザープロフィール.md」に外出しされ、スキル本体は汎用のまま、という設計になっている。つまり「個人向けだから汎用化する」という課題は実はほぼ存在しない。

2. 一方で「秘書業務の網羅性」には明確な穴がある。日々の事務のうち、報告書・議事録づくり、提案書づくり、情報整理・ファイリング、発信物の下書きが専用スキルとして存在しない（rulesに方針だけあるものを含む）。ここが体感の「網羅できていない」の正体。

したがって本提案の主眼は「汎用化」ではなく「網羅範囲の拡張」に置く。

## 対象外にする領域（意図的に実装しない）

秘書業務でも、次はAI秘書の責任範囲・技術制約から外し、専用サービスに任せる。誇大表現を避けるため、FAQ／READMEにも「AI秘書の範囲外」と明記する。

| 領域 | 外す理由 |
|---|---|
| 出張手配・交通/宿泊予約 | 実予約は物理的にできない。予約サイト・旅行代理店の領域 |
| 契約管理・契約書作成 | 法的責任を持てない書類は作らない。契約は専門サービス・専門家の領域 |
| 名刺・連絡先の取込（OCR） | 専用の名刺管理サービスの方が精度・運用で優れる |
| 電話対応・来客取次 | 物理的な応対はできない |

いずれも「できない/やらない」を正直に伝え、代わりに何を使えばよいかを添える方針。

## 追加する4スキル（優先度順）

判定軸: ①ひとり起業家の頻度×痛み ②Claude Code単体で完結でき、AI秘書が責任を持てるか ③MIRAIとの棲み分け（経営判断はMIRAI側に残す）。

### 1. 議事録・報告書（新規スキル）
打ち合わせのメモや音声書き起こしを渡すと、決まったことだけの薄い箇条書きにせず、会話の流れ・誰が何を懸念しどう着地したかまで再現できる議事録に整える。日報・週報・月次報告のテンプレ生成も担う。既存の「rules/議事録の書き方.md」の方針を、起動できるスキルとして実体化する。テキスト整形のみなので責任範囲内。

### 2. 提案書（新規スキル）
「提案書を作って」で、宛先・課題・提案内容・見積を聞き取り、そのまま送れる提案書ドラフトを生成する。既存の「書類」スキル（見積書・請求書）の隣に置く発信寄りの書類。最終判断はユーザーが行う前提。

### 3. 情報整理・ファイリング（新規スキル）
「メモ」スキルがURL・短文の保存どまりなのを補い、資料・ファイル・ナレッジを体系的に整理する。カテゴリ分け・置き場所の提案・後から探せる索引づくり。Google Drive連携がある場合はDrive上の整理も案内する。

### 4. 発信下書き（新規スキル）
メルマガ・SNS・ブログの下書きを、既存「rules/使用ツール.md」の媒体別フォーマットに沿って生成する。配信ツール（UTAGE/MyASP/Mailchimp）に合わせた形で、配信前バリデーション（プレースホルダー残存・件名重複・署名・絵文字）まで通す。送信はしない（下書きまで）。

## 使い勝手の改善（コマンド暗記の不要化）

IT苦手なひとり起業家にとって「決まったコマンドを覚えないと使えない」のは大きな壁。ここを2点で直した。

1. 意図ルーティング。`rules/秘書.md` の通常稼働に「ユーザーは決まった言葉を覚えなくてよい。どんな言い方でも裏のやりたいことを汲んで最適スキルに繋ぐ」という原則を追加し、トリガー語の一致を待たずに意図で判定する方式に変えた。

2. 「案内」スキルの新設。「何ができる？」「助けて」「〇〇したいんだけどどう言えばいい？」に、機能名の羅列でなく「困りごと→こう話しかければいい」の形で答える。具体的なやりたいことには、コマンドを教えるより先に実行へ繋ぐ。AI秘書の範囲外（出張予約・契約書・名刺取込・電話来客）は正直に伝えて代替を出す。

この「コマンドを覚えなくていい」はオプトページ・ステップメールの訴求点としても使う。

## 訴求ルール（全成果物共通）

スキルの「数」は今後も増える。「14スキル」のような具体数はオプトページ・ステップメール・README・企画・note原稿のどこでも訴求に出さず、「日々の事務をまるごとサポート／使うほど対応範囲が広がっていく」というトータルサポートの見せ方に統一する。
